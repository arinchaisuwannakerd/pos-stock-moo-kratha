# ระบบจัดการร้านย่างให้หมูกระทะ บ้านน้องโฟค กาญจนบุรี

**Module :** การจัดการการขายหน้าร้านและการตัดสต็อกวัตถุดิบ (POS & Inventory Management)

**Programmer :** นายพงศพัทธ์ ดวงจิตต์ · นายอริญชัย สุวรรณเกิด · นางสาวแสงรัส จองดี

ระบบรับออเดอร์หน้าร้านแบบ A La Carte สำหรับโต๊ะ 20 โต๊ะ ชำระเงินด้วยเงินสด / โอนเงิน / QR Code
ออกใบเสร็จรับเงิน และ **ตัดสต็อกวัตถุดิบอัตโนมัติตามสูตรอาหาร (BOM) ทันทีที่บันทึกการขาย**
พร้อมแจ้งเตือนวัตถุดิบใกล้หมด และรายงานยอดขาย/สต็อกที่ส่งออกเป็น Excel หรือพิมพ์เป็น PDF ได้

## เริ่มใช้งาน

### 1. เปิดฐานข้อมูล PostgreSQL

ต้องเปิดโปรแกรม **Docker Desktop** ก่อน แล้วรัน

```bash
docker compose up -d db
```

ฐานข้อมูลจะขึ้นที่ `localhost:5432` — ชื่อฐานข้อมูล `pos_stock` ผู้ใช้ `pos_admin` รหัสผ่าน `pos_pass123`

> อยากดูข้อมูลผ่านหน้าเว็บ ให้รัน `docker compose up -d` (ขึ้นทั้ง db และ pgAdmin) แล้วเปิด http://localhost:5050
> เซิร์ฟเวอร์ฐานข้อมูลถูกลงทะเบียนไว้ให้อัตโนมัติแล้ว คลิกที่ชื่อ **POS & Stock** แล้วใส่รหัสผ่าน `pos_pass123`

### 2. สร้างตารางและข้อมูลตั้งต้น

```bash
cd backend && npm install && npm run db:migrate
```

### 3. เปิด Back end

```bash
cd backend && npm start
```

ตรวจว่าทำงาน: เปิด http://localhost:4000/api/health

### 4. เปิด Front end

```bash
cd frontend && npm install && npm run dev
```

เปิด http://localhost:5173

## ทดสอบผ่าน Postman

1. เปิด Postman → **Import** → เลือกสองไฟล์ในโฟลเดอร์ `postman/`
   - `POS-Stock.postman_collection.json` (80 requests)
   - `POS-Stock.postman_environment.json`
2. เลือก Environment มุมขวาบนเป็น **POS & Stock — Local**
3. รัน `1. Authentication → เข้าสู่ระบบ (เจ้าของร้าน)` ก่อน — token จะถูกเก็บลง `{{token}}` อัตโนมัติ
4. จากนั้นเรียก request อื่นได้เลย หรือกด **Run collection** เพื่อทดสอบทั้งชุดตามลำดับจริง

โฟลเดอร์ `5. ขายหน้าร้าน — Flow หลัก` ออกแบบให้รันเรียงกันตั้งแต่เปิดบิล → สั่งอาหาร →
ตรวจว่าตัดสต็อกจริง → สั่งเพิ่ม → เช็คบิล → QR → ชำระเงิน → ใบเสร็จ

รันจากบรรทัดคำสั่งก็ได้:

```bash
npx newman run postman/POS-Stock.postman_collection.json -e postman/POS-Stock.postman_environment.json
```

> **ก่อนกด Run collection ให้รัน `npm run db:migrate` ก่อนทุกครั้ง**
> เพราะ test script ตรวจตัวเลขสต็อกและยอดเงินแบบเป๊ะ ๆ (เช่น "หมูสไลซ์ต้องลดลง 0.8 กก. พอดี")
> ถ้าฐานข้อมูลมีการขายค้างอยู่ ตัวเลขจะไม่ตรงและ assertion จะไม่ผ่าน
> ด้วยเหตุผลเดียวกัน อย่ารัน `npm test` กับ Postman ต่อกันโดยไม่ล้างฐานข้อมูลระหว่างกลาง

## หลักการทำงานที่สำคัญ

### การตัดสต็อกตามสูตรอาหาร (BOM)

เมนูแต่ละรายการผูกกับวัตถุดิบผ่านตาราง `recipes` เช่น *ชุดหมูกระทะเซ็ตกลาง 4 ท่าน* ใช้หมูสไลซ์
0.8 กก. เนื้อวัว 0.3 กก. ผักกาดขาว 0.8 กก. ฯลฯ

เมื่อบันทึกรายการอาหารเข้าบิล ระบบจะ**ตัดสต็อกทันทีในทรานแซกชันเดียวกัน**:

1. ตรวจก่อนว่าวัตถุดิบพอหรือไม่ — ถ้าไม่พอจะปฏิเสธพร้อมบอกว่าขาดอะไร (HTTP 409)
2. ล็อกแถววัตถุดิบด้วย `SELECT … FOR UPDATE` กันยอดเพี้ยนเมื่อหลายโต๊ะสั่งพร้อมกัน
3. หักยอดคงเหลือ แล้วเขียนบรรทัดลง `stock_movements` ทุกครั้ง (บัญชีเดินสะพัด ตรวจย้อนหลังได้เสมอ)
4. ถ้ายอดคงเหลือหลังตัดต่ำกว่าจุดสั่งซื้อขั้นต่ำ จะส่ง `stock_alerts` กลับมาให้หน้าจอแจ้งเตือน

การยกเลิกรายการหรือยกเลิกทั้งบิลจะ **คืนวัตถุดิบกลับคลังอัตโนมัติ** (movement ประเภท `RETURN`)

### สถานะโต๊ะ

`FREE` ว่าง → `OCCUPIED` กำลังใช้งาน (มีบิลเปิดอยู่) → `BILLING` รอชำระเงิน → กลับเป็น `FREE` เมื่อปิดบิล

ฐานข้อมูลบังคับด้วย partial unique index ว่า **หนึ่งโต๊ะเปิดบิลค้างได้ครั้งละ 1 ใบเท่านั้น**

### การสั่งเพิ่มระหว่างทาน

รายการอาหารเก็บ `round_no` แยกรอบ ทำให้หน้าจอแสดงเป็น "รอบแรก / สั่งเพิ่มรอบที่ 2 …" ได้
และตรวจสอบย้อนหลังได้ว่าลูกค้าสั่งอะไรเพิ่มตอนไหน

### ฝั่งลูกค้า

ลูกค้าสแกน QR ที่โต๊ะ → เปิด `http://<เครื่องแม่ข่าย>:5173/customer/T05` สั่งอาหารเองได้
โดยไม่ต้องล็อกอิน ทุกปลายทางผูกกับหมายเลขโต๊ะเสมอ จึงเข้าถึงได้เฉพาะบิลของโต๊ะนั้น

## รายงานที่มีในระบบ

| รายงาน | ปลายทาง | ส่งออก |
|---|---|---|
| ยอดขายรายวัน / รายสัปดาห์ / รายเดือน | `GET /api/reports/sales?group=day\|week\|month` | CSV, พิมพ์ |
| อันดับเมนูขายดี | `GET /api/reports/top-menu` | CSV, พิมพ์ |
| วัตถุดิบคงเหลือ | `GET /api/reports/stock` | CSV, พิมพ์ |
| วัตถุดิบใกล้หมด (Low Stock Alert) | `GET /api/reports/stock?only_low=true` | CSV, พิมพ์ |
| การรับเข้าและเบิกใช้วัตถุดิบ | `GET /api/reports/stock-movements` | CSV, พิมพ์ |
| บิลขายรายใบ | `GET /api/reports/bills` | CSV, พิมพ์ |
| สัดส่วนช่องทางชำระเงิน | `GET /api/reports/payment-methods` | CSV |

ทุกรายงานเติม `?format=csv` เพื่อดาวน์โหลดไฟล์เปิดใน **MS-Excel** ได้ (ไฟล์มี BOM ให้อ่านภาษาไทยถูกต้อง)
ส่วน **PDF** ใช้ปุ่ม "พิมพ์ / PDF" บนหน้าเว็บแล้วเลือกปลายทางเป็น *Save as PDF*
